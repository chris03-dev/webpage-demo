# SportsPro Technical Support v2

This is a full-stack CRUD application that provides management services for the SportsPro Technical Support suite.

## Structure

The project structure should contain these files and directories at minimum:

```
SportsPro/
├── client1/
│   ├── static/
│   ├── Dockerfile
│   └── nginx.conf
│
├── client2/
│   ├── static/
│   ├── Dockerfile
│   └── nginx.conf
│
├── init-db/
│   └── init_tables.sql
│
├── proxy/
│   ├── Dockerfile
│   └── nginx.conf
│
├── server/
│   ├── Dockerfile
│   ├── express.js
│   └── package.json
│
├── docker-compose.yml
├── .env.example
└── ...
```

## Setup

### Dependencies

You must first install the following dependencies:

- [Docker Engine](https://docs.docker.com/engine/)
- [Docker Compose](https://docs.docker.com/compose/)

Installing [Docker Desktop](https://docs.docker.com/desktop/) is also recommended for beginners, since it provides an accesible way to manage Docker containers and images using a GUI.

### Other Dependencies

The following dependencies are automatically provided just by building the application:

- Node.js
- PostreSQL
- Nginx

You are **not required** to install these dependencies directly in your computer's host environment. However, if you plan to migrate from a Docker-based environment for any reason, you must keep note of these dependencies.

### Build

1. Navigate to the directory `SportsPro/`, following the above **Project Structure**, using your file manager of choice.
2. Run the shell program provided by your operating system.
	- On **Windows**, open Command Prompt or PowerShell.
	- On **Linux** and **macOS**, open the Terminal.

3. Run the following command:
	```
	docker compose up --build -d
	```

## Usage

If you have completed the build instructions by this point, you can access and interact with specific parts of the application through these origins:
- `http://localhost:5000`: HTTP server (light mode)
- `http://localhost:5001`: HTTP server (dark mode)
	- `http://localhost:80`: HTTP server through Nginx
		- If you want to see load balancing in action, reload a page without cache by using the keyboard combo `[Ctrl] + [Shift] + [R]`
- `http://localhost:3000`: API server
- `http://localhost:5432`: SQL server

If you want to restart the application, run this command:
```
docker compose up
```

To stop the application:
```
docker compose down
```

To view the logs generated by the application:
```
docker compose logs
```

## API Endpoints

You must communicate to the API server at `http://localhost:3000` in order to obtain and modify the data within the SQL server. Your client must also support cookies, since it is required for authentication.

Most API endpoints are follow a simple authorization heirarchy:

- **Customers** may use customer-designated API endpoints
- **Technicians** may use the above API endpoints, as well as technician-designated API endpoints
- **Administrators** may use all of the above API endpoints, as well as administrator-designated API endpoints

Other API endpoints require role-specific identification, which makes them incompatible with this authorization heirarchy. These API endpoints shall be labeled as `[role] ONLY`.

Here is the full list of the API endpoints:

```
GET    /api/countries           List all countries

POST   /api/auth/admin          Authenticate as administrator
POST   /api/auth/technician     Authenticate as technician
POST   /api/auth/customer       Authenticate as customer

GET    /api/products            (customer) List all products
GET    /api/products/:code      (customer) List details of product matching code
POST   /api/products            (admin) Add product
POST   /api/products/search     (customer) List all products with search functions
PUT    /api/products/:code      (admin) Update product
DELETE /api/products/:code      (admin) Delete product

GET    /api/technicians         (technician) List all technicians
GET    /api/technicians/:id     (technician) List details of technician matching id
POST   /api/technicians         (admin) Add technician
POST   /api/technicians/search  (technician) List all technicians with search functions
PUT    /api/technicians/:id     (admin) Update technician
DELETE /api/technicians/:id     (admin) Delete technician matching id

GET    /api/customers           (customer) List all customers
GET    /api/customers/:id       (technician) List details of customer matching id
POST   /api/customers           (admin) Add customer
POST   /api/customers/search    (customer) List all customers with search functions
PUT    /api/customers/:id       (admin) Update customer
DELETE /api/customers/:id       (admin) Delete customer matching id

GET    /api/incidents           (technician) List all incidents
GET    /api/incidents/:id       (technician) List details of incident matching id
POST   /api/incidents           (admin) Add incident
POST   /api/incidents/search    (technician) List all incidents with search functions

PUT    /api/incidents/:id       (technician ONLY) Update incident
PUT    /api/incidents/assign/:id (admin) Assign technician to incident
DELETE /api/incidents/:id       (admin) Delete incident matching id

GET    /api/registrations/      (customer) List all product registrations
GET    /api/registrations/from  (customer ONLY) List all product registrations by a customer
POST   /api/registrations       (customer ONLY) Add new product registration
```
